# 개발 기록 — 특수 능력 시스템

> 대상: 「우리는 아직 『 』입니다 — 대국」 (nan-duel-m1)
> 기준 설계: `docs/분기후보_특수능력.md` (능력 3종·각 1회·3종 공용, 확정본)
> 원칙: 상태는 store 한 곳 / 모듈은 이벤트로 통신 / 수치·텍스트는 데이터 / 로직은 순수함수.
> 이 문서는 구현 진행을 단계별로 남긴다(무엇을·왜·어떻게 검증했는지). 제출용 "AI 활용 기술 문서"에도 재사용.

## 확정 규칙 (요약)

- 공유 산 유지. 능력은 점수가 아니라 "판을 흔드는 행동".
- 3종 공용(플레이어=AI 동일), 대국 시작 시 보유, **각 능력 국(round)당 1회**, 국 바뀌면 리셋.
- 예언서(beforeDraw·정보) / 각색(beforeDiscard·손패 장르 변경) / 복선(insteadOfDraw·버림패 회수).
- 횟수·peek 장수 등은 `config.abilities`로 분리 → 숫자만 고쳐 밸런싱.

## 핵심 설계 판단 (구현 전 코드 재점검에서 도출)

- **뽑기 전 입력 구간이 없다** → 기존 `main.advance()`는 내 턴에 자동으로 뽑고 decide로 넘어감.
  예언서·복선은 "뽑기 전"에 써야 하므로, **"조건부 정지"** 채택:
  내 턴이고 뽑기 전 쓸 능력(예언서/복선)이 남아 있을 때만 자동 뽑기를 멈추고 능력 바를 띄운다.
  능력이 없거나 다 썼으면 예전처럼 자동 뽑기 → 평범한 턴엔 군더더기 없음.
- **각색 ↔ 수읽기 정합성**: 각색은 손패 카드를 같은 단계의 다른 장르 카드(실존 id `${genre}-${stage}`)로
  치환 → `handEval`이 그대로 동작. 다만 "수읽기(남은 장수)" 표시가 한 장 어긋남 → 원본이 미룬 이슈, v1 유지.
- **각색의 카드 치환은 실존 id로** → 판정·렌더 재사용, 유령 카드 없음.

## 1단계 — 데이터 · 순수 로직 · 상태

**새 파일**
- `src/data/abilities.json` — 능력 3종 정의(id·이름·kind·timing·설명). 텍스트/성질만.
- `src/logic/abilities.js` — 순수함수:
  `initAbilityState(cfg)`(국 시작 잔여), `canUse`/`spend`(예산),
  `applyForesight(wall,n)`(다음 n장 미리보기, 산 불변),
  `applyAdapt(hand,i,genre,cardMap)`(장르 교체·단계 유지),
  `applyForeshadow(hand,discards,i)`(버림패 회수).

**수정**
- `src/data/config.json` — `abilities` 블록(enabled·uses·peek 등) 추가.
- `src/logic/duel.js` — `newRound`에 `abilityInit` 받아 국마다 잔여 초기화(→ 리셋 자동).
  능력 상태 전이 3종: `useForesight`(→{round,peek}), `useAdapt`, `useForeshadow`(→decide, 산 불변).
  기존 호출/테스트와 하위호환(3번째 인자 기본값).

**검증**
- `test/abilities.mjs` 신규 25종 통과. 순수함수 불변성(원본 미변경)·산 불변·사용 차감·페이즈 전이 확인.
- 회귀: 헤드리스 48/0, 스모크 23/0 유지.

## 2단계 — 엔진 배선 (조건부 뽑기 전 정지)

**수정**
- `src/main.js`:
  - `abilities.json` 로드, `abilityInit`(공용) 계산, `newRound`에 전달.
  - `playerHasPreDraw(round)`: 내 턴에 예언서 또는 (버림패 있는) 복선이 남았는지.
  - `advance()` draw 분기: 위 조건이면 **자동 뽑기 정지**(능력 바 렌더 후 입력 대기).
  - 능력 intent 7종 배선: `foresight`·`draw`·`foreshadow-start`·`foreshadow-commit`·
    `adapt-start`·`adapt-commit`·`ability-cancel`. 선택값은 기존 컨벤션대로 `ui`에 쓰고 paramless intent.
  - 국/매치 시작 시 능력 관련 `ui` 초기화(`ABILITY_UI_RESET`).

## 3단계 — 능력 UI

**새 파일**
- `src/render/abilityUI.js` — `#ability-bar`(능력 버튼·잔여 표시)와 `#ability-panel`(트레이) 렌더.
  예언서 미리보기(순번 1·2·3), 복선 버림패 선택, 각색 장르 선택(현재 장르 제외).

**수정**
- `index.html` — `#ability-bar`, `#ability-panel` 컨테이너 추가.
- `src/input/controls.js` — 능력 바/트레이 클릭을 intent로 위임(선택은 `ui`에 기록).
- `css/style.css` — 능력 바·트레이·장르 버튼 스타일(기존 팔레트 재사용).
- `src/main.js` — `renderAll`에 `renderAbilities` 추가.
- `test/smoke.mjs` — `abilityUI.js`를 임포트·DOM id 검사 목록에 포함.

**검증 (헤드리스 + 실제 브라우저)**
- 노드 테스트: 능력 25/0, 헤드리스 48/0, 스모크 24/0(DOM id 22개·intent 14종 모두 배선).
- 브라우저(Chromium/Playwright) 통합 12/0, 콘솔·페이지 에러 0건:
  · 뽑기 전 정지에 예언서+뽑기 표시, 손패 7장
  · 예언서 → 다음 3장 미리보기, 잔여 0
  · 뽑기 → 손패 8장(decide)
  · 카드 선택 → 각색 → 현재 장르 제외 4종 제시 → 장르 변경(무협·결 → SF·결), 단계 유지, 잔여 0
- 스크린샷으로 배치·연출 육안 확인.

## 현재 상태

- 플레이어는 예언서·각색·복선을 실제로 사용할 수 있음(각 국 1회).
- **AI는 아직 능력을 쓰지 않음**(4단계). 예언서는 정보형이라 결정적 AI엔 효과가 작아 v1에서 비중 낮음.
- 배포: 로직·UI 모두 반영됐으나, 커밋·푸시는 `NAN-업데이트-올리기.bat`으로 사용자가 진행.

## 남은 단계

- 4단계: AI 능력 사용 v1(복선=회수로 완성/개선, 각색=텐파이 개선; 예언서 보조). 자가대국 완주 확인.
- 5단계: 능력을 섞은 시뮬로 "판 흔들림"·무크래시 관찰, 밸런스 재점검, 배포.
- 후속: 개인화(3종 중 선택), 테마별 색, 각색↔수읽기 정합성 보정.
