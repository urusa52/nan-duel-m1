# 분기 후보 — 특수 능력 시스템 (검토용, 미구현)

> 상태: 설계 분기 후보. 유저와 대화로 도출(2026-07-22). 구현 결정 전.
> 목적: "규칙이 마작 같다 / 테마가 규칙과 안 엮인다" 불안의 해법 후보.

## 한 줄

공유 산·마작식 수싸움은 그대로 두고, 그 위에 플레이어별 **특수 능력**을
한 판에 1~2회 쓸 수 있게 얹는다. 능력은 **점수가 아니라 판을 흔드는 행동**을 준다.

## 왜 이 방향인가

- 점수 밸런스를 안 건드림: 지금까지 난제였던 "완성 점수 분포"(점수표·AI 참기로도
  안 변함, D41)를 우회. 능력은 점수가 아니라 선택·상호작용을 늘림.
- 수싸움 유지: 공유 산에서 뽑는 구조 그대로 → 남은 패 세기·상대 읽기 살아있음.
- 테마를 손끝에: 능력 이름이 "이야기 쓰기"의 언어(복선·각색·예언). 서고 세계관이
  드디어 플레이에 체현됨.
- 마작과 차별화: 마작은 뽑고 버리는 것 외 행동이 없음. 능력이 "언제 쓸까"라는
  새 판단 축을 더함.

## 확정된 선택 (유저)

- 공유 산 유지 (가챠식 산 설계는 제외 — 원래 D16/D23 아이디어와 구분).
- 능력 획득 방식: **기본 능력 1~2회 사용** (대국 시작 시 보유, 발동 타이밍은 선택).
  · 대안이었던 "산에 특수 패 섞기"(순수 운)는 보류. 나중에 추가 요소로 합칠 여지.
  · 선택 이유: 목표(쉬운 게임)에 맞음(계획 가능), "언제 쓸까" 전략 생김,
    유지보수 쉬움(능력·횟수를 config/data로).
- 보유 방식: **3개 공용으로 시작** (플레이어·AI 둘 다 같은 3개를 갖고 시작).
  개인화(고르기)는 능력이 판에서 잘 도는 걸 확인한 뒤 다음 단계로.

## 확정된 능력 3종 (프로토타입)

성격이 셋 다 달라 서로 안 겹침: 수싸움 / 완성 유도 / 실수 만회.
전부 점수 무관 — 판을 흔드는 행동만 준다.

### 1. 예언서 (수싸움)
- 효과: 산의 맨 위 3장을 미리 본다 (나만 봄, 상대에겐 안 보임).
- 발동: 내 차례, 뽑기 전에 사용 가능.
- 판단 포인트: "지금 미래를 알면 버림 선택이 유리한가" — 위기 때 아껴 쓰기.
- 구현 메모: 산 배열 끝 3개를 UI에 잠깐 표시. 상태 변경 없음(읽기만).

### 2. 각색 (완성 유도)
- 효과: 손패 한 장을 골라 그 장르를 다른 장르로 바꾼다 (단계는 유지).
- 발동: 내 차례, 뽑은 뒤 버리기 전.
- 판단 포인트: 완성 한 장이 안 맞을 때 억지로 맞추는 카드 — 강력하므로 1회.
- 구현 메모: 손패의 카드 하나를 교체(genre만 변경한 가상 카드). handEval 재사용.

### 3. 복선 (실수 만회)
- 효과: 내가 이전에 버린 패 하나를 손으로 되가져온다 (대신 다른 한 장을 버림).
- 발동: 내 차례, 뽑기 대신 사용(그 턴은 산에서 안 뽑음).
- 판단 포인트: 잘못 버린 결정적 카드를 되찾기. "뽑기 한 번을 포기할 가치가 있나".
- 구현 메모: 내 버림패에서 1장 회수 + 손패 1장 버림. 산 잔량 불변.

### 사용 횟수 (확정)
- **각 능력 1회씩**, 한 판(국) 기준. 국이 바뀌면 리셋.
  · 각색이 강해서 2회는 과할 수 있음 → 우선 1회로 통일하고 시뮬로 재조정.
  · config로 능력별 횟수 분리 → 나중에 "예언서만 2회" 같은 조정 가능.

## 데이터 형태 (구현 시)

```
abilities.json:
  [
    { id:"foresight", name:"예언서", uses:1, timing:"beforeDraw", ... },
    { id:"adapt",     name:"각색",   uses:1, timing:"beforeDiscard", ... },
    { id:"foreshadow",name:"복선",   uses:1, timing:"insteadOfDraw", ... }
  ]
config.json:
  abilitySet: ["foresight","adapt","foreshadow"]  (공용 3종)
```

## 남은 미결 (구현 중 결정)

- 능력이 상대에게 보이는가(발동 사실·잔여 횟수) vs 숨기는가 → 수싸움 정보.
  기본안: 발동 사실은 보이되(연출), 예언서로 "무엇을 봤는지"는 비공개.
- AI가 능력을 언제 쓸지 (v1은 단순 규칙: 위기 시/완성 근접 시).
- 테마별 색깔(먼치킨·빙의물 등)과 능력 연결 → 이후 탐색. v1은 공용 3종.

## 규모 감각

- 로직: duel의 페이즈에 "능력 사용" 행동을 추가. 능력별 효과 함수(순수함수).
  각 능력이 상태를 어떻게 바꾸는지 정의 필요. 중간 규모.
- 데이터: 능력 정의(id·효과·횟수)를 abilities.json 등으로 분리.
- UI: 능력 버튼·발동 연출. render/input에 얇게 추가.
- 밸런스: 점수를 안 건드리므로 점수 시뮬은 그대로. 대신 "능력이 판을 얼마나
  뒤집나"를 자가대국으로 관찰 필요.
- 목표 정합 주의: 능력이 많아지면 초보에게 복잡. 처음엔 2~3종으로 시작 권장.
