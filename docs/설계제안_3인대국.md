# 설계 제안 — 3인 대국 (검토용 초안)

> 상태: 제안. 유저 확인 전까지 구현 착수 안 함.
> 기준: 구상정리_마스터_v1.md, ARCHITECTURE.md (M1' 2인 코어).
> 목표 정합: "잘 모르는 사람도 쉬운 마작류" — 이 문서의 모든 선택은 이 잣대로 판단.

## 0. 왜 3인인가 (유저 의도)

- 완성이 더 자주 터지길 / 판이 북적이고 이해가 쉽길 원함.
- 사실: 인원↑ → 각자 뽑기 횟수↓ (자력 완성은 더 어려움).
  대신 버림패↑ → 운명 뺏기 기회↑ → 완성이 뺏기 위주로 자주 발생.
- 리스크: 초보가 추적할 버림패가 2인분 → 정보량 증가 (목표와 상충 가능).

## 1. 모듈 영향 요약

| 모듈 | 변경 | 사유 |
|---|---|---|
| wall | 없음 | 산은 인원 무관 |
| handEval / yakuEval | 없음 | 한 사람 손패 판정, 인원 무관 (핵심 재사용) |
| 데이터(config/cards/yaku) | config에 인원·좌석만 추가 | 룰 수치는 그대로 |
| duel | 중 | 턴 2인 교대 → N인 순환, 뺏기 판정 대상이 복수 |
| match | 소 | 점수 3인분, 승리 판정은 동일(선취) |
| ai | 중 | 2개 인스턴스 + 성향 차등 |
| render(table/hud) | 중 | 상대 영역 1 → 2, 점수판 3인 |
| tutorial | 소 | 문구에 "라이벌들" 반영 |

## 2. 좌석·턴 (제안)

- 좌석: player(나) → rivalL → rivalR 시계방향 고정. config.seats로 정의.
- 턴: 순환. duel.turn을 좌석 인덱스로 관리 (현 'player'|'ai' 2값 → 좌석 배열).
- 배패: 각 7장씩 (그대로). 산 60장 − 21장 = 39장으로 시작.

## 3. 운명 뺏기 우선순위 ★핵심 결정

한 명이 버린 카드로 나머지 둘이 동시에 완성 가능할 때 누가 가져가나.

후보:
- (A) 좌석 순서: 버린 사람 기준 다음 좌석부터 우선. 마작 관례. 단순·예측가능.
- (B) 고점 우선: 더 높은 점수로 완성하는 쪽. 극적이지만 초보에겐 판정이 불투명.
- (C) 뺏기 금지(자력만): 3인에선 뺏기를 아예 빼서 단순화. 완성 빈도는 인원으로만.

초보 목표 관점 추천: **(A) 좌석 순서.** 규칙이 눈에 보이고 설명 한 줄로 끝남.
※ 후리텐(자기 버림패로 뺏기 불가)은 v1 없음 유지.

## 4. AI 두 라이벌 (제안)

- 공통 두뇌는 현 ai.js 재사용. 성향만 config로 차등:
  - rivalL "성급한 이야기꾼": 빠른 완성 지향(속공형 손 선호, 뺏기 적극).
  - rivalR "신중한 편집자": 고점 지향(가산역 쌓기, 뺏기 보수적).
- 구현: aiChooseAction에 성향 파라미터(가중치) 주입. 큰 재작성 아님.
- 사고 시간도 성향별 차등 → "세 명이 각자 논다"는 체감.

## 6. 구현 순서 (확정 시)

1. config에 seats·ai 성향 추가, store를 좌석 배열로 일반화
2. duel: 턴 순환 + 뺏기 대상 복수화 (+ 헤드리스 테스트: 3인 자가대국 완주)
3. ai: 성향 파라미터 (+ 두 성향이 실제로 다르게 행동하는지 테스트)
4. render: 3인 배치 + hud (+ DOM 테스트)
5. match: 3인 점수 (+ 테스트)
6. tutorial 문구, smoke 갱신

## 7. 검토가 필요한 결정 (유저)

1. 뺏기 우선순위: A(좌석) / B(고점) / C(자력만) 중?
2. AI 두 성향: 위 제안대로 / 다르게 / 둘 다 같은 수준?
3. 초보 완화(위협 상대 ⚠ 표시): 넣기 / 빼기 / 나중에?
4. 그 전에: A+B 2인 버전을 먼저 플레이하고 결정할지?
